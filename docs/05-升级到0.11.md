### 迁移实际改了什么

只有三处 API 变化，一处顺带修正：

| 位置 | 0.6.5 | 0.11.16 |
| --- | --- | --- |
| 导入 | `from cadgen import build123d as bd` | `import build123d as bd` |
| 导入 | `from cadgen import step` | `from cad import step` |
| 装饰器 | `@step(out="../STEP/x.step")` | `@step("../STEP/x.step")` |
| 读文件 | `read_scene(p)` / `read_step(p)` | `step.read(p)` + `cad.build123d.leaves(tree)` |

顺带修掉的：`src/gripper.py` 在**模块层**读 `bd.Align.CENTER`——
新契约下这会让脚本自己的进程也加载内核，每次 run 多花 2～3 秒。改成函数里读。

### 怎么验证迁移没走样

写了 `checks/compare_steps.py`：读两个 STEP，比零件数、包围盒 min/max、标签集合。

```
gripper:              ✓ 零件数 4   ✓ XYZ 尺寸差 0.000000 mm  ✓ 标签一致
robotiq_v_finger:     ✓ 零件数 3   ✓ XYZ 尺寸差 0.000000 mm  ✓ 标签一致
robotiq_v_finger_single: ✓ 零件数 2 ✓ XYZ 尺寸差 0.000000 mm  ✓ 标签一致
```

**几何完全一致**。这个脚本留着，以后改模型时也拿它当回归测试。

## 为什么要升

| | 现在（本机） | 上游最新 |
| --- | --- | --- |
| 运行时 | `cadgen 0.6.5`（2026 年中的版本） | `cad 0.11.16`（2026-11-23 当天还在推 commit） |
| 命令名 | `cadgen` | `cad`（`cadgen` 保留为弃用别名） |
| skill 数量 | 13 个（按**文件格式**划分） | 8 个（按**产出**划分） |
| 架构 | 跑脚本 → 写文件 | **常驻引擎 + 文档模型 + 实时 viewer** |
| 机器人描述 | 只能手写 URDF | **能从 CAD 模型直接生成 URDF/MJCF** |
| 关节限位 | 手工填 | `cad model ranges <id>` **自动从几何干涉推** |
| MCP | 无 | `cad-mcp`，Claude Code 可直接接 |

**最关键的一条**：你要做的"看数模之间的关系、把 URDF 里关键值调到合理位置"，
在上游有现成实现——`models/mujoco/` 那个样例项目就是干这个的：

```
厂商原始 STEP → 读成模型 → 把零件归组成 link → 从几何找关节轴
→ 声明材料 → 导出 URDF → 生成 MuJoCo 文件 → 跟 Menagerie 和厂商原版对比
```

我们现在的 0.6.6 工具链**完全没有这个能力**。

## 升级会发生什么

上游给的安装方式就一条命令：

```bash
curl -fsSL https://texttocad.dev/install.sh | sh
```

它做五件事：

1. 没装 `uv` 就装（旧的会升级）
2. 把 `cad` 当 **uv tool** 装上（最新 release）
3. 已装的话用 `cad update` 升到**同一大版本**的最新
4. `cad plugin install` —— 把插件装进**你机器上每一个 agent 应用**
   （Claude Code、Codex、Cursor、Gemini…），并**清掉旧版留下的东西**
5. `cad plugin update auto on` —— 打开自动更新

> ⚠️ **它会动你机器上所有 agent 应用的配置**，不只是这个项目。
> 这是个全局动作，值得先看一眼再说"好"。

## 会砸到我们什么

上游的迁移文档写得很直白：**0.8 不留任何向后兼容层**——
没有 shim、没有别名、没有报错提示"你应该用新名字"。

### 我们项目里会炸的三处

| 现在的写法 | 0.11 的情况 | 新写法 |
| --- | --- | --- |
| `from cadgen import build123d as bd` | ❌ **ImportError**。`build123d` 这个名字 0.8 就拿掉了 | `from cad import build123d as bd` |
| `@step(out="../STEP/x.step")` | ❌ `step` 现在是**类型**不是装饰器；`out=` 参数也没了 | `@model` 装饰 + `cad model export <id> ../STEP/x.step` |
| `read_scene(...)` | ❌ 同样在 0.8 被拿掉 | `cad.step.read(...)` / `step.inspect(...)` |

**不会炸的**：`from cadgen import step` 本身还能用（`cadgen` 是 `cad` 的别名模块，
同一个对象），只是会打一条 `CadDeprecationWarning`。

### OpenCascade 也要换

0.8 把 build123d 从 **0.11 + OpenCascade 7.9** 换成了
**0.13 + OpenCascade 8.0**（`cadquery-ocp-novtk 8.0.x`）。

只碰 build123d 高层 API 的模型**基本没事**；
直接 import `OCP` 的会撞上一批重命名：

```python
# 旧
from OCP.TopTools import TopTools_IndexedMapOfShape
TopoDS.Edge_s(shape)
xmin, ymin, zmin, xmax, ymax, zmax = box.Get()

# 新
from OCP.collections import IndexedMap_TopoDS_Shape_TopTools_ShapeMapHasher
TopoDS.Edge(shape)
lo, hi = box.CornerMin(), box.CornerMax()
```

我们的 Robotiq 项目**只用了 build123d 高层 API**（`bd.Box`、`bd.Pos`、`bd.Cylinder`…），
应该不受影响。但 `checks/inspect_robotiq.py` 用了 `read_scene`，要改。

完整对照表在
[`docs/migrations/migrating-to-opencascade-8.md`](https://github.com/earthtojake/text-to-cad/tree/main/docs/migrations)。


### 2. 验证


## 升级后的新能力（值得花时间看）

| 命令 | 干什么 |
| --- | --- |
| `cad model ranges <id>` | **自动推关节限位**：让每个关节单独转到子连杆撞上父连杆为止，打印每个止点（度或毫米） |
| `cad model export <id> f.urdf` | 从 CAD 模型导出 URDF（框架、限位、质量、惯量、网格全从内核出） |
| `cad model inspect <id> '<ref>'` | 查引用 |
| `cad model dfm <id> --process ...` | 可制造性检查（替代旧 `dfm` / `dfam-check`） |
| `cad mujoco check` | MuJoCo 模型健康检查 |
| `model.param(...)` | **人能直接在 viewer 里调参数**，模型自动重跑 |
| `cad run mujoco-studio` | 开 MuJoCo Studio |

`model.param` 这个设计值得单独说：
以前"改一个尺寸"要改代码重跑；现在**看图的人直接在 viewer 里拖一个数字**，
模型跟着重算。对"和朋友一起迭代设计"特别有用。
