### ② 朋友发来的 MicroDuck 标定支架（**还没动手**）

朋友发来一张设计图，问题是"恢复原中间夹柱后，怎样稳住鸭"，
给了两个方案：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A. 原架加一条侧面束带 | 利用原架侧窗，蓝色可拆软带 | 打印用料 +0 g，维修多一次系带 |
| B. 用脚座自带的斜面 | 前倾 22°，脚座绕前缘翻到维修面 | 整套试切多 35.3 g，约多 1 h 08 min |

**这正是本仓库该接手的活**：把两个方案都建成参数化模型，
量出实际用料差异和干涉情况，再决定。输入是一张图，输出是能切的模型 + 数字对比。

难点在图上量不准的部分（斜面角度、束带走向、夹柱位置），需要问清楚而不是猜。

### ③ MicroDuck 本体的"数模关系"（**还没动手**）

> "看数模之间的关系，把关键值调整到合理的位置"

MicroDuck 是 [Pollen Robotics](https://pollen-robotics.com/microduck/) 的开源双足鸭
（25 cm 高、800 g、14 个 Dynamixel XL330 舵机），
[上游仓库 `pollen-robotics/microduck` ★14k](https://github.com/pollen-robotics/microduck)（Apache-2.0）。

**关键事实：MicroDuck 的机器人描述是 MuJoCo 的 MJCF，不是 URDF。**

```
kinematics/assets/alpha/robot_walk.xml     ← 机器人描述（MJCF）
scripts/bake-duck-mesh.py                  ← 网格烘焙：MJCF+STL → duck.bin
robotctl/assets/duck.bin                   ← 板上跑的紧凑二进制（几千三角形）
```

15 个关节，限位长这样：

```xml
<joint axis="0 0 1" name="left_hip_yaw"  type="hinge" range="-0.4363323129985824 0.5235987755982988" />
<joint axis="0 0 1" name="left_hip_roll" type="hinge" range="-0.3839724354387516 0.38397243543875337" />
<joint axis="0 0 1" name="right_hip_yaw" type="hinge" range="-0.5235987755982988 0.4363323129985824" />
```

这些不是随手填的数：
`-0.4363…` = −25°，`0.5236…` = +30°，
**是从 Dynamixel XL330 的舵机限位经减速比换算来的**；
左右髋偏航是镜像的（左边 −25°..+30°，右边 −30°..+25°）。

**已经能看出来的数模不一致**（`bake-duck-mesh.py` 注释里写的）：

> `mouth` 是一个舵机，但**没有对应的 MJCF 关节**（下颌是固定 geom），
> 所以它永远不会出现在烘焙结果里。

这类"实体在、关节不在"或"关节在、限位对不上舵机"的问题，
正是"把关键值调整到合理的位置"要处理的。

**好消息**：本机已经装了 `mujoco`，而且社区有
[`jonathanhawkins/microduck-lab` ★169](https://github.com/jonathanhawkins/microduck-lab)
——在**普通 Apple Silicon Mac、无 CUDA GPU**上训练 MicroDuck 策略、浏览器里实时看。
所以"改完数模 → 仿真验证"这条闭环在这台机器上走得通。
