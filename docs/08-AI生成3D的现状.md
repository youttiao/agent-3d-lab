# AI 生成 3D 的现状，以及机械件那条差距（2026 秋）

> 这份文档是 2026-11-23 两轮深度调研的浓缩结论，只写**查证过**的东西。
> 每条都标了来源和证据等级；查不到的就写「查不到」，不写「不存在」。
>
> 调研方法：arXiv API、GitHub API、厂商自己的页面、HuggingFace model card。
> **不采信中文聚合博客的数字。**
>
> 目的：回答两个问题 ——
> ① 「AI 生成 3D」现在到底到哪一步了？
> ② 我们做的事（机械件、参数化、能上机器人）离它还有多远？

## 0. 一句话结论

> **对机械件来说，AI 生成 3D 这条路的瓶颈不是「像不像」，是「能不能用」。**
>
> 2026 年的模型能把一个零件渲染得很像，但产出的**不是 CAD**：
> 没有 B-rep、没有特征树、没有公差、没有绝对尺度，
> 而且**大部分连切片都不通过**。

三个数字（都有独立测量支持）：

| | 数字 | 含义 |
| --- | --- | --- |
| **可切片率** | 好的 **90%**，差的 **7–17%** | Hi3D 1536³ 能切 90%；TRELLIS.2 只剩 17%，Pixal3D 只剩 7% |
| **体积误差** | **TRELLIS 317.9%**，Hunyuan3D-2 109.4%，InstantMesh **5,515.5%** | OmniMech（25.1 万张带尺寸标注的工程图，arXiv 2608.05539）——**目前唯一对这些模型做的尺寸测量** |
| **三角面预算** | 中位数 **77,402 面**，**79.8%** 的资产超过 Unity 的 3 万面移动端上限 | 要 CAD/打印基本得事后抽稀 10–100 倍，而抽稀改变拓扑 |
| **绝对尺度** | 几乎全被毁掉 | Hi3D 明确归一化到单位最大半径；TRELLIS/Pixal3D 输出单位 AABB 网格。只有 Tripo 的 `auto_size` 承诺真实米制 |

> 📌 **配套的一篇**：[`09-build123d会怎么坑你.md`](09-build123d会怎么坑你.md)
> —— 我们自己这套栈（build123d / OCCT）的实测失败模式，
> 以及「先量再说做完了」这条被独立测量过的工作方法。

## 1. 2026 年的分裂：这是一个**表示形式**的选择，不是建模能力的问题

Hi3D 3.0 论文（arXiv 2610.11685）对 TRELLIS.2 一族的批评，一句话点破了整个领域：

> while **O-Voxel/FaithC offers high representational precision, it often suffers from poor surface quality and non-watertight geometry.**

于是分成两派：

| | 派别 | 代表 | 实测可切片率（SSR） |
| --- | --- | --- | --- |
| **A** | 拓扑保真优先，牺牲水密性 | TRELLIS.2、Pixal3D（都基于 O-Voxel） | **17%** / **7%** |
| **B** | 可制造性优先 | Hi3D v1.0 / Twinkle3D（SPAR3D 系，后处理补洞 + 取最大连通块）、Direct3D-V3（训练时加流形正则） | **90%** |

A 派把「开放曲面 / 非流形几何 / 内部封闭结构」当卖点写在 README 里，
然后微软自己的 model card 又叫你「对需要严格水密几何的应用（比如 3D 打印），
我们另外提供了网格后处理脚本」。

### ⚠️ 最关键的一条：只看 CLIP/ULIP 指标会把排名排反

Hi3D 的实测里，**TRELLIS.2 在语义/CLIP 空间质量上赢 Hi3D**：

| | ULIP-2 ↑ | Uni3D ↑ | 可切片率 SSR ↑ |
| --- | --- | --- | --- |
| TRELLIS.2 | **49.32** | **44.18** | 17% |
| Hi3D | 48.07 | 42.14 | **90%** |

> **任何停在 CLIP/ULIP 指标上的评测，对制造场景来说会把这两者排成完全相反的顺序。**

这是本次调研对「我们该走哪条路」最直接的支撑：
**语义像 ≠ 能用。**

## 2. 独立的几何普查：2307 个真实资产，23 个生成器

最强的跨模型独立测量是 **Topoheal 3D asset census**
（[topoheal.com/census/](https://topoheal.com/census/)，仓库 `topoheal/3dqa-benchmark`，
引擎 `pip install 3dqa`，资产来自 3D Arena 数据集，MIT）。
同一个引擎、同一个版本、同一套阈值，n = 2307。

### ⚠️ 先说不能引用的

普查自己的 README 写着，**逐生成器的缺陷率已被作者撤回**：

> ### ⚠️ The figures that were published in this file have been retracted. … A re-lint on **2026-08-17** (FINDING-7) superseded the heal rates, and three open findings undermine the per-generator defect-rate table.

所以那些广为流传的数字 —— **「TRELLIS.2 91.1% 非水密 / 14.9% 非流形」** ——
（TRELLIS #363、Hunyuan3D-2 #370 都引用了它）**是作者撤回的，不要当现状引用**。

### 能引用的（普查 v1.0，2026-08-17 重跑）

| 生成器 | 资产 | 中位面数 | **未通过 lint** | 完全修复 / 部分 / 修不了 | 修复引入的新缺陷 |
| --- | ---: | ---: | ---: | --- | ---: |
| **全体** | 2307 | 77,402 | **1461** | 63.7% / 33.6% / 2.7% | **312** |
| TRELLIS.2-4B | 101 | 290,881 | **101 (100%)** | 26.7 / 73.3 / 0 | 70 |
| Hi3DGen | 101 | 632,684 | **101 (100%)** | 77.2 / 22.8 / 0 | 20 |
| TripoSR | 97 | 60,876 | 97 (100%) | 90.7 / 9.3 / 0 | 2 |
| **TRELLIS v1** | 100 | 16,403 | **35 (35%)** | 17.1 / 8.6 / **74.3** | 0 |
| SPAR3D | 101 | 29,936 | 9 (9%) | 100 / 0 / 0 | 0 |
| SF3D | 101 | 24,128 | 5 (5%) | 100 / 0 / 0 | 0 |
| Hunyuan3D-2.1 | 101 | 40,000 | 4 (4%) | 75.0 / 0 / 25.0 | 0 |
| **Hunyuan3D-2** | 101 | 40,000 | **0 (0%)** | — | 0 |
| 404_GEN / LGM / SAM-3D-Objects-3DGS | 101 | **0（无法测量）** | — | — | — |

**这张表说出来的四件事：**

1. **Hunyuan3D-2 是全集里最干净的生成器（0/101 失败）** ——
   SDF→marching cubes 的路子 + 水密训练数据，确实兑现了。
2. **TRELLIS.2-4B 100% 过不了几何检查**，而且修复后效果很差
   （只有 26.7% 完全修好），修复工具自己还引入了 70 个新缺陷。
   TRELLIS v1 的 35% 反而好得多，因为它自带的 `to_glb` 里有 pymeshfix + 可见性 mincut。
3. **修复工具不是免费的。** 普查自己的结论：
   > Repairing these assets introduced **312 new defects** that were not in the original files…
   > **A repair tool that reports no regressions has not looked for them.**
4. **Hi3DGen 的 100% 失败是「能力缺失」不是「缺陷」** ——
   100% 没有 UV（它本来就不出纹理），100% 超过 Unity 的 3 万面上限。
   它切片是好的。这说明**「未通过 lint」不是个好指标**，可比可切片率更好。

### 普查自己的范围限制（原文）

> It reads triangle meshes: .glb .gltf .obj .ply .stl. **It cannot do B-rep, so STEP, IGES and Parasolid are outside it entirely, and there is no tolerance check at all.**
> It has no opinion on whether an asset looks right. It measures geometry, not art direction.

**普查覆盖不到的**：Pixal3D、Step1X-3D、SUPRA-Tex、Direct3D-S2/V3、PartCrafter、
Hunyuan3D-Omni/Part、Tripo H3.1、Hi3D 3.0。

## 3. 这些模型输出的到底是什么（**不是 CAD**）

| 维度 | 现状 |
| --- | --- |
| 表示 | 全部是三角网格（GLB/OBJ/PLY/STL 起步；腾讯云 3.1 Pro 加了 STL/USDZ/FBX，Tripo 支持 FBX 四边面）。**没有一个产出参数化/B-rep 实体、特征树、GD&T 或公差** |
| 尺度 | **基本都被破坏**（见 §0） |
| 面数 | 中位数 77,402；TRELLIS.2-4B 29 万，TripoSG 136 万，Hi3DGen 63 万 |
| 纹理 | **两极分化**：要么全 PBR（TRELLIS.2、Hunyuan3D-2.1、Pixal3D、3DTopia-XL、SUPRA-Tex），要么**完全没有**（Hi3D、Direct3D-S2/V3、Hunyuan3D-Omni/Part、MeshAnything）。RGB-only 居中。**TRELLIS v1(2024) 到 Hunyuan3D-2.1(2025-06) 之间，没有任何模型出 PBR** |
| 单体 vs 多部件 | 基本都是**单个连通网格**。多部件的只有 Hunyuan3D-Part、PartCrafter（都是「N 个零件装一个 glb」） |
| 水密性 | **2025–26 的模型里，只有 Hi3D v1.0 和 Direct3D-S2/V3 产出「构造上水密」的网格** —— 而且都是**后处理**（耳切补洞 + 取最大连通块 / 学习式内部剥离）。唯一「原理性」的路子是 Hi3D 3.0 / Twinkle3D 的训练时流形目标，**但没开源** |

### 一条重要的负面结论

arXiv 上用 `all:"3D printing" AND all:"image-to-3D"`、
`all:"printability" AND all:"mesh generation"`、
`all:"manifold" AND all:"mesh generation"` 检索，
**没有任何 2026 基准报告「一批生成器里有多少比例的网格是水密/流形/可切片的」**。

Hi3D 的 SSR 表是事实上的唯一一把尺子，8 个基线、单一切片器
（Bambu Studio / PrusaSlicer CLI）、单一配置、单一尺度（最长 AABB 边 100 mm）、**不做修复**。
绝对值不可移植，但**排序**和 Topoheal 普查一致
（TRELLIS.2 100% 失败、TRELLIS 35% 失败、Hunyuan3D-2 0% 失败）。

## 5. 机械件：现状（2026 秋）

### 5.1 ⚠️ **没有**「Agent 拿真实打印机/机械臂当反馈闭环来验证 CAD」的论文

这是本次调研最重要的负面结论。截至 2026-11-23，arXiv 上**不存在**这样的工作。
存在的是四个层次：

| 层 | 反馈到底是什么 | 最好的例子 |
| --- | --- | --- |
| **1. 真硬件、真反馈** | 造出来的机器人实地跑，Agent 看视频改设计 | **RoboBuilder**（arXiv:2611.23855，2026-11-18） |
| **2. 刚体仿真** | 用 Chrono + Bullet 仿真验证机构 | **FunCAD-Harness / FunCADBench**（arXiv:2610.26861） |
| **3. 切片/工艺规则反馈** | 45° 悬垂检测、DFM 规则、G-code | **AgentsCAD**（arXiv:2607.02448） |
| **4. 只有渲染 + 内核测量** | 渲染图 + OpenCASCADE 量尺寸 | CADSmith、Adam、Zoo Zookeeper |

**而本机在用的 text-to-cad 自己就写明了它做不到：**

> Today the skill hands a print to Bambu Connect or Bambu Studio, where you start it:
> **it does not start, pause or cancel a print or read printer status, and it never asks for an access code.**
> … **It cannot see your printer.**

它的 DFM 检查语义也写得很清楚：
`OK`（退出码 0）/ `FAILED`（1）/ `NOT CHECKED`（3）——
**「It is never a pass」**；
`A rule with no figure for your material or technology is not_evaluated, which is not a pass.`
`A mesh cannot be checked for holes, pins or fine detail.`

### 5.2 基准：做「功能」的很少，做「形状」的很多

| 基准 | 是什么 | 关键数字 |
| --- | --- | --- |
| **CAD-bench**（**ICML 2026 workshop poster，不在 arXiv**） | 17 个任务、4 个难度档，含**螺纹配合对**和**功能性齿轮系**；导出几何后做尺寸/位姿校验 + **Blender 刚体仿真** | 最强的单模型 **59.9%**；**功能性任务对大多数单模型接近 0** |
| **Parametric CAD Bench v3**（arXiv 2611.02659） | 100 个任务 = 30 文本→CAD + 30 创建并编辑 + 40 **工程图→机械件**；要求**原生 FreeCAD 文档**（不只是脚本或导出的 B-rep） | 2026-09-24 快照：13 个模型-Agent 组合，**Claude Code + Opus 5.5 = 61.03% 总体，84.66% 图生 CAD** |
| **BenchCAD 1.0**（arXiv 2605.10865） | **17,900 个执行验证过的 CadQuery 程序，106 个工业零件族**（锥齿轮、压簧、扭钻…） | — |
| **Text2CAD-Bench**（arXiv 2605.18430） | 600 个人工标注样本，L1–L4 难度梯 | **IR（无效率）从 ~15% 涨到 70–90%** |
| CADENA-Bench（arXiv 2608.00799） | **3396 个真实零件**（轴与衬套 762 / 齿轮与轴承 749 / 弹簧与紧固件 1046 / 平板与杠杆 464 / 壳体与框架 359 / 工装与量具 17） | ⚠️ **这是 mesh→CAD（逆向）基准，不是 text→CAD** |

**Text2CAD 那个数字最扎人**：

> Text2CAD achieves the lowest IR (as far as 2%) yet the **highest CD (220) and near-zero IoU**…
> indicating that it consistently generates **executable code without capturing geometric specifications**.

**代码能跑 ≠ 尺寸对。** 这和我们在本机遇到的是同一件事 ——
`cad urdf validate` 通过，和 MuJoCo 实际加载出来的东西是两回事。

还有一条值得记：Text2CAD-Bench 的 L4（100 个真实世界样本）明确限定
**「All L4 examples consist of a single solid body without assemblies,
mating constraints, or hidden internal mechanisms.」**
—— 真实机械件里最难的装配和约束关系，基准里根本没有。

### 5.2b ⭐ 「Done Is Not Correct」—— 直接在我们这套栈上做的

**arXiv 2611.10063**，用的就是 **build123d / OpenCASCADE**（和我们同一套）。

| | 数字 |
| --- | --- |
| 单次生成的 agent 声称完成的比例 | **98%** |
| 其中**静默做错**的比例 | **14.1%** |
| 加上「先量再声明」的循环后 | **3.2%**（p < 10⁻⁴），声明精度 **64% → 96%** |

> *"Crashes are cheap to catch: a spec that fails to execute announces itself.
> **The expensive failure is a part that builds and renders plausibly while its bolt circle
> sits on the wrong pitch diameter, delivered with 'done, confidence 0.97.'**"*

151 次失败拆开看：**95 次压根没产出有效实体**，**56 次产出了有效几何但语义检查没过** ——
主要特征是**内部特征缺失或尺寸错**、**整体包络尺寸错**。

> 🔑 **降到 4–5% 靠的是「声明契约」，不是更强的模型。**
> "the reduction to 4–5% comes from **the claim contract**, not from capability."

这条直接定义了我们这个仓库的形状。详见 [`09-build123d会怎么坑你.md`](09-build123d会怎么坑你.md)。

### 5.2c BenchCAD 的逐特征召回率：圆角和沉头孔基本是 0

arXiv 2605.10865，17,900 个执行验证过的 CadQuery 程序，106 个工业零件族。逐操作召回率：

| 操作 | gpt-5.3 | gpt-5.3-thinking | 样本数 |
| --- | ---: | ---: | ---: |
| extrude | 83.3 | 84.4 | 90 |
| workplane | 86.3 | 77.4 | 124 |
| union | 65.3 | 59.7 | 72 |
| **hole** | **60.2** | 55.4 | 83 |
| cut | 44.1 | 32.2 | 59 |
| **cutThruAll** | **16.2** | 10.8 | 37 |
| **revolve** | **14.3** | 10.7 | 28 |
| **chamfer** | **8.6** | 4.3 | 70 |
| **loft** | **5.9** | 23.5 | 17 |
| **fillet** | **0.0** | 12.0 | 25 |
| **cboreHole** | **0.0** | **0.0** | 3 |
| **mirrorY** | **0.0** | **0.0** | 4 |
| 执行成功率 | 69.5 | 67.5 | — |

> **要一个 ⌀6 H7 带沉头孔的孔，沉头孔做对的概率是 0.0%。**
> 论文结论："models often approximate the final geometry with simpler primitives
> instead of recovering the intended parametric construction."

它还给了我们那个 bug 的正式名字（**F01**）：

> **F01 (L1) wrong_param_value** — "Right operation, wrong numerical value:
> dim, diameter, radius, length, or angle written off-target;
> geometry shape-correct but a single number misses."
> 代表案例："Model writes radius **5.6** when prompt asks for **5.85**; cylinder topology unchanged."

→ **形状对、数字错** —— 这正是我们 V 槽案例三个 bug 的类别。

还有一条对我们「结论靠看图」这条原则的**重要修正**：

> "replacing the textual edit instruction with a target render **collapses every model to near-zero,
> since a render specifies geometry but not numbers.**"

**渲染图能告诉你形状，告诉你不了数字。** 所以出图和量，两样都要。

### 5.3 mesh → CAD：确定性方法完胜学习方法

这是本次调研对「我们要不要走 mesh→CAD」的决定性数据。

| 系统 | 表示 | CADENA-Bench IoU / GMS / IR | 强在哪 | 弱在哪 |
| --- | --- | --- | --- | --- |
| **mesh2cad**（**确定性**，非学习） | 原生 STEP + CadQuery/OpenSCAD/FreeCAD 脚本 | 不在 CADENA 上 | 干净的 CAD 来源板/支架/盒/螺栓孔阵列：**6 个 Prusa 零件全部精确 STEP**，Hausdorff ≤ 0.22 mm，体积误差 ≤ 0.39% | 0.2 mm 噪声下的圆角半径与沉头孔；球面；自由曲线/加强筋轮廓 |
| **CADFather** | CadQuery，多工具 Agent | **0.909 / 0.721 / 0.0%** | CADENA 全场最好 | 弹簧 GMS 0.672、齿轮 0.660；滚花和浅槽丢失；每个零件 307 秒 |
| **CADMAGEDDON** | CadQuery **和原生 FreeCAD** | IoU 0.981 / GMS 0.909（60 件子集） | 曲面类型保真最好；**齿轮的齿、叶轮的叶片能还原**；单张 48 GB GPU 能跑 | **没有具名参数**；圆角/倒角是显式实体而非边操作 |
| CADENA-RL | CadQuery，逐步 | 0.876 / 0.670 / 1.6% | 已发表的学习方法里最好 | 齿轮与轴承（58.1）；被遮挡的内部结构 |
| CADEvolve | CadQuery，进化语料 130 万 | 0.730 / 0.529 / 10.8% | 覆盖面广 | 齿轮与轴承（41.3） |
| cadrille | CadQuery，多模态 + GRPO | 0.688 / 0.498 / **0.8%** | 有效性最好 | 曲面类型保真 |
| CADReasoner | CadQuery，带渲染迭代 | 0.683 / 0.529 / **39.9%** | DeepCAD/Fusion360 干净件 + 扫描仿真 | 约一半失败是 OpenCASCADE 造不出来的退化三点弧 |
| CAD-Recode | CadQuery 草图拉伸（Qwen2-1.5B） | 0.686 / 0.489 / 27.9% | 草图拉伸件 | 其他一切；训练分布窄 |

**CADMAGEDDON 自己的限制说明（原文）**：

> The emitted CadQuery **can be edited, but its dimensions are literal values rather than named parameters**,
> and **fillets and chamfers are explicit solids rather than edge operations**;
> **recovering design intent is beyond the current system.**

→ 这就是**「mesh→CAD 作为几何」和「mesh→CAD 作为设计意图」之间的那道坎**。

**本轮调研的最终判断（也是最该记住的一句）：**

> 在真实机械件上，**确定性路径（mesh2cad）比任何学习路径都可靠得多** ——
> mesh2cad 能把 6 个 Prusa 零件做成精确 STEP；
> 最好的学习系统（CADFather）在齿轮/轴承上 GMS 只有 0.66、弹簧/紧固件 0.67，
> CADMAGEDDON 仍然产不出具名参数。
>
> 2026 年的现状应该表述为：
> **「mesh → 可编辑参数化机械 CAD」对简单基本特征已解决，对真实零件未解决。**

## 6. 顺便更正几条流传很广的说法

| 说法 | 更正 |
| --- | --- |
| 「CADENA-Bench 是 text→CAD 基准」 | ❌ 它是 **mesh→CAD（逆向）** 基准 |
| 「Text2CAD 是 arXiv 2412.04253」 | ❌ 是 **2409.17106** |
| 「CADENA-Bench 的六个零件族是 shafts/bushings/bearings、gears/frames/levers…」 | ❌ 实际是 shafts & bushings / gears & bearings / housings & frames / flat & levers / springs & fasteners / tooling & gauges（注意弹簧和紧固件是一族，且 1046 个，占最多） |
| 「`earthtojake/text-to-cad` 是 Zoo 的 Text-to-CAD」 | ❌ **完全是两个东西**。text-to-cad 是独立开源插件（build123d + OpenCASCADE，全本地，MIT）；Zoo 的 Text-to-CAD 只开源**语言**（KCL）和文档，**几何内核是闭源托管的付费 API** |
| 「KCL 有 X 星」 | ❌ `KCL-Language/kcl` 和整个组织目前都是 404，**不要引用星数** |
| 「RoboBuilder 用 3D 打印机验证 CAD」 | ⚠️ 不准确。它是**真实机器人**上跑（3D 打印件是真的），但那是**整机协同设计**基准，不是「打印来验证 CAD」 |
| 「text-to-cad 能看打印机状态」 | ❌ 它自己写明 **"It cannot see your printer."** |

## 7. 查不到 / 没验证的（**明说，别当结论**）

1. **TRELLIS.2 是「CVPR 2026 最佳学生论文」** —— arXiv 条目里没有获奖备注，
   仓库自己的 BibTeX 写的是 `journal = "Tech report", year = 2025`。唯一来源是第三方聚合站。**未证实。**
2. **Hi3D 3.0 / Twinkle3D 的代码和权重** —— GitHub 仓库全 404，HF 组织里只有 v1.0。**未验证。**
3. **Hi3D 普查里那行 `Hi3DGen`** —— 语料快照是 2026-08-01，**早于 Hi3D v1.0 开源（2026-10-23）**，
   那是托管产品的输出，版本未知。**不要等同于 v1.0。**
4. **CAD-bench 的逐任务清单** —— 只有摘要，海报在登录墙后。
5. **Hunyuan3D 检出的 checkpoint 到底有多大概率非水密** —— 没有 GPU 实跑，issue 里只有个例。
6. **没有独立复现 Hi3D 的 SSR 数字**（作者自己跑的，单切片器单配置）。
7. **HuggingFace 的 model card 无法用 curl 取**（TLS 被拦），多数是从仓库 README 读的。
8. **没有系统扫过 HuggingFace 的 `image-to-3d` trending**（WebSearch 配额耗尽）。**这是本次调研最大的覆盖缺口。**

## 8. 对我们的意义

| 结论 | 出处 |
| --- | --- |
| **机械件继续走代码参数化（路线 A）** | AI 生成网格那派给的是「像」不是「能制造」；而且没有绝对尺度、没有公差、没有特征树 |
| **mesh→CAD 只在「干净基本特征」上可靠** | mesh2cad 6/6 精确 STEP vs 学习方法 GMS 0.66–0.72；**而且「具名参数」这件事到今天没解决** |
| **要衡量就用「能不能切片 / 能不能装上」，别用 CLIP 分数** | TRELLIS.2 在 ULIP-2 赢 Hi3D，在 SSR 上 17% vs 90% |
| **功能性的东西（装配、螺纹配合、齿轮系）现在是空白** | CAD-bench 最强单模型 59.9%，**功能性任务接近 0**；Text2CAD-Bench 的真实件全是「单个实体，无装配无隐藏机构」 |
| **校验器通过 ≠ 能用** | Text2CAD「IR 最低却 CD 最高、IoU 近零」；我们自己的 `cad urdf validate` 报 0.81 kg 而 MuJoCo 实际 0.06 kg |
| **代码能跑 ≠ 尺寸对** | "Done Is Not Correct"：98% 声称完成，**14.1% 静默做错**；BenchCAD 的圆角召回 0.0%、沉头孔 0.0% |
| **出图和量，两样都要** | BenchCAD：「render specifies geometry but **not numbers**」；CADFather 消融：**去掉确定性拟合，掉的分远多于去掉优化器** |
| **没有「打印验证 CAD」的先例** | text-to-cad 自己说 **"It cannot see your printer."**；RoboBuilder 是整机协同设计，不是打印验证 |

**这最后一条对我们是好消息**：我们还没做的事，暂时也没人做成。
