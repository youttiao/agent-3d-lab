## 已验证的几个关键事实（本机实测）

### ✅ OCCT 无头渲染在这台 Mac 上直接可用

```bash
cad step snapshot STEP/x.step tmp/x.png            # 0.07～2 秒
cad model snapshot <id> tmp/x.png --camera top     # 预设视角
```

1600×1200，**不用浏览器、不用 GPU**。
（0.6 时代靠 Playwright + Chromium 渲染，现在 OCCT 自带光栅器直接画。）

> 这条原本是最大的不确定项——macOS 的 OpenGL 从 10.14 起就废弃了，
> 官方 OCCT 8 的光栅器能不能在无头 arm64 上初始化，没人验证过。**现在验证过了。**

### ✅ 中国网络下安装可用

pip 配的是阿里云镜像。实测这个镜像对这套包**是新的**：

| 包 | 镜像最高版本 | 需要 |
| --- | --- | --- |
| `build123d` | 0.13.0 | 0.13.0 ✓ |
| `cadquery-ocp-novtk` | 8.0.1.1.0（含 macosx_11_0_arm64 wheel） | 8.0.1.1 ✓ |
| `cad` | 0.11.16 | 0.11.16 ✓ |

> ⚠️ **一个坑**：PyPI 的 simple 索引**不是按版本排序的**（按上传时间）。
> 用 `tail` 看会以为镜像很旧。用 `sort -V | tail -1` 才是最高版本。

### ✅ `cad` 自己也带 MCP

`cad-mcp` 是 `cad` 的别名包，装好就有，Claude Code 插件会自动用上。
不用单独配 MCP server。

## 还缺什么（按用途选装）

### A. 想让 Agent 直接"看见"并操作 3D 软件

| 装什么 | 怎么装 | 换来的能力 |
| --- | --- | --- |
| **Blender** | `brew install --cask blender` | 有机体/曲面建模、场景、渲染。也可 `pip install bpy`（macOS arm64 有 wheel，但**只支持 cp313**） |
| **FreeCAD** | `brew install --cask freecad` | GUI 参数化 CAD + 机器人装配，有社区 MCP server（`neka-nat/freecad-mcp` ★3.4k） |

> ⚠️ 社区版 Blender MCP 的 `execute_blender_code` 是**无沙箱执行任意 Python**。
> 开 `BLENDER_MCP_SAFE_MODE=1` 更稳（默认关）。
> 官方的 Blender Lab MCP 也一样没有防护，且**默认端口 9876 和社区版撞**。

### B. 想真的打印出来

`brew install --cask orcaslicer`（或 prusa-slicer）。
`print3d` skill 需要真实切片器 CLI 才能出片。

### C. 想做网格层面的活

| 装什么 | 用途 |
| --- | --- |
| `trimesh` | 网格分析/修整/凸包（做碰撞体最常用） |
| `yourdfpy` | URDF 解析与遍历 |
| `pyvista` / `vtk` | 网格可视化（⚠️ macOS 上离屏渲染要走 OpenGL，没有 xvfb 等价物） |

### D. 想跑仿真

**MuJoCo 已经随 cad 装好了**（`cad[mujoco]`，首次用到时自动下载）——
但那是 cad 的集成环境，**你自己 Python 里的 `mujoco` 是另一份**。

| | 版本 | 说明 |
| --- | --- | --- |
| 本机系统 Python | `mujoco 4.0.1` | ✅ **已升级**（原 3.12.0 会静默忽略 URDF `<mimic>`） |
| `cad[mujoco]` | 0.11.16 集成 | 供 `cad mujoco check` 用 |
| `trimesh` | 5.2.2 | ✅ 已装。网格分析 / 质量属性 / 凸包 |
| `yourdfpy` | 0.0.60 | ✅ 已装。URDF 解析与遍历 |

```bash
python3 -m pip install "mujoco==4.0.1" trimesh yourdfpy
```

> ⚠️ **MuJoCo 4.0 把包拆开了**（`mujoco-core` / `mujoco-studio` / `mujoco`）。
> 从 3.x 升级时 3.x 的残留目录会让 `import mujoco` 直接报
> `ModuleNotFoundError: No module named 'mujoco._specs'`。
> 修法：`pip install --force-reinstall --no-deps mujoco mujoco-core`

> ⚠️ macOS 无头用 **`MUJOCO_GL=disable`**。
> MuJoCo 4.0 在 import 时校验这个变量，而 **`osmesa` / `egl` 是 Linux 专属**——
> 在 macOS 上设 `MUJOCO_GL=osmesa` 会直接 `RuntimeError`。

> ✅ 两个 MuJoCo 静默坑都已在本机复现并确认：
> `<mimic>` 现在生效、`fusestatic="false"` 能救回 base link 的质量。
> 一键体检见 [`checks/urdf_probe.py`](../checks/urdf_probe.py)。

另外 [`jonathanhawkins/microduck-lab`](https://github.com/jonathanhawkins/microduck-lab)
能在**普通 Apple Silicon Mac、无 CUDA GPU** 上训练 MicroDuck 策略。

> ⚠️ **Isaac Sim 在 macOS 上永远不会有**（要 Ubuntu/Windows + RTX 4080 起步，
> 且"没有 RT Core 的卡不支持"）。所以路线 E 的现实选择只有 MuJoCo / Gazebo / Genesis / Newton。

### E. 想玩 AI 生成网格

| 装什么 | 现实情况 |
| --- | --- |
| 本地跑 Hunyuan3D / TRELLIS **官方仓库** | **需要 NVIDIA GPU**（8–24 GB 显存），Mac 上装不上 —— 官方仓库依赖 `flash-attn`、`spconv`、`nvdiffrast`、`CuMesh` 等 |
| 走 API（Meshy / Tripo / Zoo.dev） | Mac 完全能跑，但要钱，出的网格**不可参数化** |

> 详见 `docs/01-技术路线全景.md`：**机械件别走这条路**，走参数化代码。

#### E2. 但 Mac 上其实有三条真能跑的路（本机 18 GB 实测分档）

| 路线 | 仓库 | 内存 | 说明 |
| --- | --- | --- | --- |
| **SF3D（官方，最省事）** | `Stability-AI/stable-fast-3d` | 低 | 纯 Python，贴图烘焙带**自研 Metal kernel**。`PYTORCH_ENABLE_MPS_FALLBACK=1` 即可。⚠️ 作者建议 **<32 GB 用 CPU 版**（`SF3D_USE_CPU=1`）；⚠️ 仓库自 2025-01-22 停更 |
| **Hunyuan3D-2.1 MLX（要 PBR 纹理）** | `dgrauet/Hunyuan3D-2.1-mlx` | INT8 ≈6 GB / INT4 ≈4 GB | **最省内存**。M2 Pro 上 512px 6 视角约 9 分钟，输出 4096² PBR。⚠️ Metal 光栅器处理不了 Stage 1 的 ~50 万面，会先重网格化到 ~4 万面 |
| **trellis.cpp（要 TRELLIS.2 的质量）** | `pwilkin/trellis.cpp`（MIT，411★） | 峰值 5.6 GB + 权重 16.5 GB（有 q4） | 纯 C++/GGML，**运行时不需 Python**，macOS 上 Metal 默认开。官方实测 M5 24GB → 512 分辨率带纹理 GLB **9 分 21 秒**。⚠️ **没有预编译 macOS 二进制**，要自己 `cmake -B build -G Ninja` 编译 |

**本机 18 GB 的分档**：SF3D 轻松 · Hunyuan3D-2.1 MLX INT8 舒适（≈6 GB）·
trellis.cpp q4 理论可行但**未实测** · Hi3D v1.0 MLX 只够 512 分辨率且很紧。

> ⚠️ **三个坑**：
> ① 有仓库叫 `trellis-mac`、`trellis2-apple` 声称提供「TRELLIS.2 Apple Silicon 移植」——
> **是伪造的，不要跑它的安装脚本**；
> ② 微软至今**没合并** Apple 支持（TRELLIS PR #359 / #357 未合并）；
> ③ ComfyUI 已在 2026-08-22 合入 TRELLIS.2 + Pixal3D 原生节点，
> 但**没有任何官方声明说这些节点在 MPS 上能跑** —— 「可能但未验证」。

**云 GPU**（agent 可调用）：Replicate T4 $0.000225/s · L40S $0.000975/s ·
fal.ai trellis $0.02/次 · trellis-2 $0.25–0.35/次。
⚠️ **没有一家提供 OpenAI 兼容的 3D 端点**。

> 完整版（含其他模型在 Mac 上的状态、假的移植仓库、商业 API 定价表）
> 见 [`08-AI生成3D的现状.md`](08-AI生成3D的现状.md) §7 和 §10.3。

## 隐私

`cad` 默认开启遥测（只发计数，不发文件名、路径、prompt）。

```bash
cad telemetry off        # 关掉
DO_NOT_TRACK=1           # 或用这个环境变量
```

> 本次安装期间 **没有关**——留着是有意为之，等你决定。
> 另外安装器在**失败时**会发一条匿名失败报告（成功不发）。
