**三个必须先知道的"信息纠错"**（下面多处引用，直接影响选型）：

1. **"Zoo Kernels" 这个产品不存在。** Zoo（zoo.dev）的 CAD 内核是**闭源、托管、GPU 加速、有专利**的（专利 US-12229885-B1），只通过 Engine API 暴露。开源的是**语言 KCL**（`kcl-lang/kcl`，2,448★，Apache-2.0），不是内核。同样，**"Keras" 这个 CAD 语言不存在**——那是把 KCL 和机器学习框架 Keras 混为一谈。
2. **Hunyuan 3D 许可证的阈值是 100 万 MAU，不是 1 亿。** 且有**地域排除**：欧盟 / 英国 / 韩国不在授权范围内，**生成物本身**也不能在这些地区使用。
3. **Treillis.2 的 "CVPR 2026 最佳学生论文" 无法证实。** arXiv 2512.14692 无 award 注释，仓库 BibTeX 自称 "Tech report, 2025"，官方 CVPR 奖项页 404。唯一来源是第三方聚合站。

### 1.2 关键事实（逐条）

**TRELLIS.2 ——最重要的结论是它"故意"不做水密。** 论文 §3.1.1 原文：O-Voxel *"is free from the watertight and manifold constraints, enabling robust handling of arbitrary geometry including **self-intersecting surfaces** and fully-enclosed interior structures."* HF 模型卡 Known Limitations：*"the generated raw meshes may occasionally contain small holes... For applications requiring strictly watertight geometry (e.g., 3D printing), we provide accompanying mesh post-processing scripts."* 我在 24 页全文做了关键词普查：`watertight` / `printab*` / `toleran*` / `thin wall` / `CAD` / `STEP` / `fillet` / `GD&T` / `clearance` / `through-hole` —— **全部 0 命中**。它没有文字分支，TRELLIS v1 的 text 权重没有延续过来。

**TRELLIS v1 的 text权重确实存在**（`TRELLIS-text-{base,large,xlarge}`，2025-03-25），但作者自己劝退：*"It is always recommended to do text to 3D generation by first generating images using text-to-image models..."* 它的 `outputs['mesh']` 是一个 list —— 源码 `decoder_mesh.py` 显示长度 = SLAT batch 维（默认 1），**不是"一个物体的多个零件"**，实测就是一个网格。

**Hunyuan3D 2.x 的 text 路径是坏的。** `api_server.py` 里 `self.pipeline_t2i` 被注释掉了，文本分支一调用就 `AttributeError` → 落到通用 except → 返回 404 `server_error_msg`。2.1 的 `GenerationRequest` 里**根本没有 text 字段**。Hunyuan3D-1 是唯一有可用 text 路径的开源权重。

**Hi3D v1.0 是"精修器"不是生成器**：输入是「一张参考图 + 一张粗网格」，输出是仅几何的单网格，**绝对尺度和世界坐标被破坏**（README：*"Input world-space position and absolute scale are not preserved"*，归一化到单位最大半径）。它的粗网格可选由 Hunyuan3D-2mini 生成——**但 Hi3D 自身基于 SPAR3D(Sparcubes)，不是 Hunyuan**。

**Hi3D 的 90%/17%/7% 切片数据是全领域唯一的可打印性横向测量**，我已从技术报告 PDF（仓库内 `docs/Hi3D_v1.0_Technical_Report.pdf`，9 页）直接提取原文确认方法学：Bambu Studio 的 PrusaSlicer CLI、A1 0.4mm 喷嘴、PLA、统一缩放到最长 AABB 边 = 100 mm、**切片前不做任何网格修复**、成功 = 生成 >200 字节的 G-code。⚠️ 四个必带警告：(1) 厂商自测；(2) **测试样本数 N 从未公布**；(3) 评估 harness 未开源；(4) 作者自己写 *"Watertightness and successful slicing ... do not guarantee physical manufacturability."*

**这张表还有一个反直觉之处**：SSR 随分辨率**下降**（256³=97%、512³=100%、1024³=80%、1536³=7~17%）。模型分辨率越高，细薄特征越多，越切不动。

**Pixal3D 的 7% 是 Hi3D 测的，Pixal3D 自己从未声明过任何可打印性指标。**

**两个独立测量的排序一致（这很关键）**：Hi3D SSR 排序 ≈ Topoheal 几何质检排序。

**Topoheal 3D 资产普查**（`topoheal/3dqa-benchmark`，n=2,307 资产 / 23 个生成器 /同一引擎同一阈值）——⚠️ **重要：该仓库 README明确声明旧的"每生成器缺陷率"表已被作者撤回（FINDING-7）**，2026-08-17 重跑后的**已发布 v1.0 表**才是可引用的：

## 2. CAD（参数化）方向：什么真的出货了，什么只是论文

### 2.1 先分清五个层级（这是全报告的骨架）

| 层级 | 拿到什么 | 能改尺寸吗 | 代表 |
|---|---|---|---|
| **A — 原生特征树** | B-rep 实体 + 应用管理的特征历史 | 能，且是尺寸级 | Zoo/KCL、Onshape FeatureScript、Fusion、FreeCAD、SolidCraft |
| **B — 通用语言脚本** | 可重跑的 Python/JS 源码，几何由源码派生 | 能，但你改的是脚本 | build123d、CadQuery、OpenSCAD、FluidCAD |
| **C — CAD 命令序列** | sketch/extrude 操作符 token 流 | 能重放，但不好人读 | DeepCAD、Text2CAD、CAD-MLLM、CADENA |
| **D — 脚本产网格** | Blender 式 Python，产出网格 | 脚本能重跑，**但几何是网格不是 B-rep** | BlenderMCP、sand3d、BlenderLLM |
| **E — 冻结网格** | STL/OBJ | **不能** | Hunyuan3D、Tripo、Meshy（属另一品类） |

**已验证的事实**：整个学术谱系里**没有任何一个工作的主交付物是冻结网格**；网格是商业 text-to-3D 品类的特征。而 §1 的模型**没有一个**产出 Tier A/B/C。

### 5.3 具体失败模式（这是最有价值的部分）

**(a) 代码优先——失败在"跑得通但错了"，而不是跑不通。**

最贴题的一篇是 arXiv 2611.10063（build123d/OCCT 上，13 任务 / 122 项可机检）：

> *"single-shot agents claimed completion on **98% of attempts and were silently wrong on 14.1%**; a tool-use loop that enforces **measure-then-claim** cut silent failures to **3.2%** and raised **claim precision from 64% to 96%**."*
>
> *"Crashes are cheap to catch: a spec that fails to execute announces itself. **The expensive failure is a part that builds and renders plausibly while its bolt circle sits on the wrong pitch diameter, delivered with 'done, confidence 0.97.'**"*
>
> *"of 151 failed attempts, 95 never produced a valid solid… and 56 produced valid geometry that failed semantic checks… the dominant signatures are **missing or mis-sized internal features** (counterbore depth or face, bore and hole extents, step sections); **a wrong envelope dimension is also common**."*

**且它明确说：修复来自"契约"而不是更大的模型**——*"the reduction to 4–5% comes from the claim contract, not from capability."*

BenchCAD（arXiv 2605.10865，17,900 个执行验证的 CadQuery 程序）的 F01 失败类原文：
> *"Right operation, wrong numerical value: dim, diameter, radius, length, or angle written off-target; geometry shape-correct but a single number misses."* 例：*"Model writes radius **5.6** when prompt asks for **5.85**; cylinder topology unchanged."*

Parametric CAD Bench v3 里一个 86 参数的桁架板任务：9/13 个系统得 0 分，*"Eight of these zeros come from the specification axis alone… geometry similarity between 0.126 and 0.445, but **12 to 80 of the 86 parameters are inconsistent or not found**"*。

**内核层面的具体坑（GitHub issue 实锤）**：
- `build123d#1363`：**布尔减运算静默失败**——*"Instead of creating a hole, the preview only displays the intersection edge… **The exported model (either step or stl) matches the preview and also contains no hole.**"* ← 一个 Ø6 的洞凭空消失。
- `CadQuery#2114`：fillet 失败时 **segfault 整个进程**（不是抛异常），会直接带走 agent 的这一轮。
- `build123d#1506`：fillet 失败信息不告诉你是哪条边，*"this is the most common thing people get stuck on"*。
- `build123d#1453`：`faces(Select.NEW)` 位置敏感，语义会崩。
- `build123d` PR #1505：**非确定性**——*"OCCT's list overload can choose a merged vertex based on memory address. The same script can therefore produce different geometry across processes."*
- `build123d#874`：Blender/扫描用米、B3D 用毫米 → *"models to be imported way too small"*。

**(b) 文生网格——三个独立的硬伤。**

1. **没有尺寸概念。** OmniMech（arXiv 2608.05539，251,000 张全尺寸/全公差 2D 正投影图）实测：*"**Hunyuan3D-2, InstantMesh, SAM 3D, and TRELLIS performed poorly on dimensioned engineering drawings, often treating the sheet as a single image and producing coarse, textured, or shallowly extruded geometry rather than the specified part.**"* 体积误差 317.9%（TRELLIS）/ 109.4%（Hunyuan3D-2）/ 5,515.5%（InstantMesh）。原话：*"such deviations represent missing features and incorrect feature characteristic, rendering reconstructed parts **unsuitable for assembly or manufacturing**."*
2. **没有孔、没有面。** Procedura（arXiv 2608.26238）实测 TRELLIS.2 第 95 百分位二面角 **73.11°**——*"a surface regressed from samples **has no notion of a face or a bore**"*，*"the natives **reproduce the silhouette faithfully but blur bolt heads, vents, and panel lines into the surrounding body**"*。
3. **不可编辑。** Zoo 的论证在技术上站得住（厂商立场，但被上面独立测量佐证）：*"In CAD, a hole is a cylinder with an axis, diameter, depth… In a mesh, a 'hole' isn't empty space, it's just part of the mesh… **There's no axis to reference, no diameter parameter to change.**"*、*"**Resolution destroys practicality.** Mechanical parts live in millimeters and tolerances. If you want to represent a 200 mm part and resolve 0.05 mm detail, you're talking about a grid on the order of 4000³ cells."*

**商用厂商自己也知道。** Tripo 的 STL Repair 工具页原话：
> **"WATERTIGHT ≠ PRINT-READY"** · *"A watertight mesh has no open boundary edges. It can still self-intersect, contain walls that are too thin… **This tool never collapses those separate questions into one promise.**"* · *"Self-intersections: **Not checked in this version.**"*

Tripo H3.1 的 `auto_size`（真实世界米制）**默认 false**。Meshy 的"可打印性分析"完整定义是：*"measuring its **watertightness, volume, holes, non-manifold edges, and degenerate faces**… You can also check **wall thickness**"* —— **没有尺寸精度、没有公差、没有配合/间隙指标**。

**社区实测**（r/meshyai，典型案例）：*"First result was close but proportions were slightly off. **The screw hole on the back wasn't there** obviously since the photo was front only."* *"Had to add a 4mm hole in TinkerCAD for the screw mount since **AI doesn't know about that stuff**."*

**(c) GUI 路线——2026 年实测很糟。**

CADWorld（arXiv 2609.16251，200 题 / 11 类 / 183 概念）：

| 模型 | 成功率 | "做完了但错了" | 平均动作数 |
|---|---|---|---|
| 人类专家 | **87.0%** | 100% | 26.5 |
| GPT-5.4 (CUA) | **17.5%** | 62.5% | 104.6 |
| Opus4.8 (CUA) | 16.0% | 49.5% | 71.8 |
| Kimi K2.6 | 7.5% | 20.5% | 93.6 |
| Qwen3.6 / MiniMax M3 | **0.0%** | 3.0% / 2.5% | 97.7 / 100.7 |

- 最好的 agent 在 Part 类只有 **22.1%**，Sketch 12.7%，**CAM / FEM / TechDraw 全模型 0%**。
- 失败分类 F1–F11 里，最贴题的两个：`F6 geometry_close_but_out_of_tolerance`（*"similar to the target shape, but its dimensions, volume, area, or placement fall outside the allowed tolerance"*）和 `F8 shape_correct_process_wrong`（*"The final shape is correct, but it was built with the wrong features, parameters, constraints"*）。
- 最有诊断价值的消融：**只保留终端输出**时，*"most of the failures were caused by 'wrong document structure'… building via the command line leads the model to build by script; therefore, **engineers can no longer make edits to the built-up sections**."* 而且去掉 harness 后 GPT-5.4 *"did not finish any task"*。结论一句话：*"In a CAD workflow, **the saved artifact is the product**."*

**(d) 桥接路线——2026 最有希望的一条。**

- **mesh2cad**（确定性、纯 Python、MIT、本地）是最强的正面证据。作用域原文：*"**plates, brackets, and boxes with holes, bolt circles, slots, bosses… countersunk and counterbored holes… and fillets**"*。6 个真实 Prusa i3 MK3S 打印零件全部恢复成**精确 STEP**，Hausdorff ≤0.22 mm、体积误差 ≤0.39%。**但失败清单同样明确**：*"At 0.2 mm [noise] the bracket falls back on every seed… one seed keeps only three of the four rounds and the Hausdorff rises to 0.85 mm."*（**倒角最先崩**）；countersink 在 >0.05 mm 噪声下就退化；*"When a fit is poor it does not invent a surface."*；范围外直接退出码 2 而不是硬编。
- **CADMAGEDDON**（arXiv 2611.22563）的架构值得单独抄下来：*"**a vision–language model chooses only the structure of each feature, and fitting supplies its values.**"* 单张 48GB GPU，FP8 Qwen3.8-27B，CADENA-Bench IoU 0.981 / GMS 0.909。它的诚实边界：*"its dimensions are literal values rather than named parameters, and fillets and chamfers are explicit solids rather than edge operations; **recovering design intent is beyond the current system.**"*
- **CADFather** 的成本对比是整份报告最实用的商业数字：*"CADFather reaches an IoU of 0.943 after four assistant steps at **$0.016 per part**, and 0.968 at its full budget of **$0.046 per part**. For comparison, **Claude Opus 5.5 and GPT-6 Astra with tools report 0.962 at $5.94 per part**."*
- **CADENA** 的四条失败模式（附录 A.7）是对"为什么 mesh→CAD 仍然不行"最干净的陈述：*"**countable features are approximated rather than counted**… the impeller and the radial fan keep the right body and the wrong blades"*；*"helical geometry outside the DSL's vocabulary is replaced by the nearest available primitive, **a thread standing in for a coil spring**"*；*"Internal cavities, blind bores and undercuts… **no amount of stepping recovers them**"*。

### 5.4 四个真实零件的横向推演（浓缩版）

| 零件 | (a) 代码优先 | (b) 文生网格 | (c) GUI | (d) 桥接 |
|---|---|---|---|---|
| **L 形支架**：4×Ø6 通孔，40×60 孔距，8mm 厚 | 最好情况可用；典型失败 = 孔存在但 Ø8、布尔静默无孔（build123d#1363）、`cutThruAll` recall 仅 16.2% | **直接失败**：孔要么没有要么不是圆；无直径、无位置、无通/盲、无公差；绝对尺寸已被破坏 | 22.1% 上限；最可能 F6 | **最强**：text-to-cad 写带 `hole_d` 命名参数的脚本；mesh2cad 的 bolt circle 原语直接对口 |
| **机器人手指节**：42mm 近节，18mm 宽，铰孔中心距精确 38.0mm | **参数化最占优**：`pivot_center_distance = 38.0` 改一下就重驱动几何。编辑任务预期只有 39–44% | **灾难性**：95 百分位二面角 73°（孔壁应 90°）→ 孔是光滑凹坑；长度是比例，"42mm" 一起丢 | 4–6 个状态相关交互；人类中位数 26.5 动作，agent 失败时 71–104 动作 | **装配/运动学最强**（Procedura 的 typed mates + FunCAD刚体仿真） |
| **相机支架**：1/4-20 螺纹凸台，Ø6.35 底孔，T槽导轨 | 螺纹是**库查找**而非生成；模型多半给一个标着"螺纹"的光孔或螺旋线 | **最危险**：*"a thread standing in for a coil spring"*——渲染完全像，拧不进去。网格螺纹没有螺距参数可改 | **少数 GUI 有优势的场合**：螺纹标准是菜单选择而非模型要编的参数 | **正解**：Zoo KCL 标准库有 holes；BuildCAD 有螺纹生成器；text-to-cad 出图带 hole callouts |
| **法兰转接头**：DN50→DN65，4×Ø18 螺栓圆，6mm 厚，3mm 圆角 | 圆角是 LLM CAD 最崩的地方：`fillet` recall **0.0%**（gpt-5.3）、8.6% chamfer；CadQuery#2114 倒角失败会 segfault | 圆角是亚体素半径特征——正是 SSR 表里崩掉的那一类（1536³ 时 TRELLIS.2 17%、Pixal3D 7%） | 旋转+图案+孔+圆角是状态相关的链式操作 | **最强**：mesh2cad 的作用域逐字覆盖这个零件；但**倒角仍是第一个崩的**（0.2mm 噪声下 Hausdorff 升到 0.85mm） |

**共同点：所有路线在这个零件上最弱的环节都是同一个——倒角。**

### 5.5 物理世界反馈：2026 年有，但很边缘

**没有任何一篇 2026 arXiv 论文让 agent 用真实 3D 打印机或机械臂作为校验机械件 CAD 的主反馈回路。** 存在四个层级：
1. **真硬件**：**RoboBuilder**（arXiv 2611.23855，2026-11-18）——135 台实体机器人手工搭建、约 240 小时、16,427 次仿真。原文极狠：*"under public part data, **none of 15 initial passing designs crossed the real course**"*；修正后 *"**66% cross the real course**: 77% at level 1, 68% at level 2 and 42% at level 3"*。agent 写的 CadQuery 零件 3D 打印后 *"rescues nine failed tasks"*。但它做的是机器人，不是通用机械件。
2. **刚体仿真**：FunCAD-Harness（2610.26861），46 个机构族。**移除诊断型反馈后 Astra 从 22 题掉到 0 题**，移除视觉只掉 2 题。
3. **切片/DFM 规则**：AgentsCAD（2607.02448）。
4. **仅渲染+内核**：CADSmith、Adam、Zoo Zookeeper。

### 6.2 Apple Silicon 实际可跑的三条路

**路线 1：SF3D 官方仓库（最省事）**
```bash
export PYTORCH_ENABLE_MPS_FALLBACK=1
python run.py --image input.png --output output.glb
```
作者建议：**统一内存 < 32GB 时跑 CPU 版**（`SF3D_USE_CPU=1`），因为 MPS 比 CUDA 后端更吃内存。⚠️ 仓库自 **2025-01-22 起未更新**，没在 PyTorch 2.15 上验证过。零依赖风险。

**路线 2：`pwilkin/trellis.cpp`（MIT，411★，2026-11-01）——我推荐的"有 PBR 纹理"的路线**
纯 C++/GGML，**运行时不需要 Python**，macOS 上 ggml 的 Metal 后端默认开启，不需要额外 flag。
- 官方实测：**Apple M5 24GB → 512 分辨率图 → 带纹理 GLB 耗时 9 分 21 秒，峰值 RSS 5.6 GB**，全部神经阶段跑在 Metal 上。
- 权重约 **16.5 GB** 磁盘；提供 **q4 量化版**。
- M1 上需 `TRELLIS_FA_FAST=1`（bf16 K/V 要 M2+）。
- ⚠️ **没有预编译 macOS 二进制**，只发 Linux/Windows，得自己 `cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release` 编译。
- ⚠️ 你的 18GB 跑512 分辨率在 5.6GB 峰值 + 16.5GB 权重（可下 q4）的约束下**理论上可行，但我未实测**。

**路线 3：`dgrauet/Hunyuan3D-2.1-mlx`（MLX 移植）——最省内存**
- 作者自己的内存表：FP16 → DiT 5.7GB / **峰值约 10GB，建议 32GB 机器**；INT8 → 3.0GB / **峰值约 6GB，16GB+**；INT4 → 1.6GB / **峰值约 4GB，16GB**。
- 实测："*~9 min for 6 views at 512px on an M2 Pro*"，输出 4096² PBR albedo + metallic-roughness。
- 已知限制：Metal 光栅器处理不了 Stage 1 的 ~50 万面原始网格，会先重网格化到 ~4 万面。
- 你 18GB：**INT8 舒适，INT4 轻松**。这是"要在 Mac 上拿到完整 PBR 纹理"的现实选择。

**路线 4（补充）：`gtrg55/trellis2-mlx`（73★）** —— TRELLIS.2 的 MLX 移植，但**只在 M4 Max 128GB 上验证过**；1024³ "several minutes"。18GB 上未验证。

**路线 5（补充）：`mlx-community/Hi3Dv1.0-mlx`** —— 官方 MLX 社区移植，M4 Pro 64GB 实测 512 分辨率 3.5 分钟 / 峰值 17GB，1024 分辨率 30 分钟 / 30GB。**你的 18GB 只够跑 512 且很紧。**

### 6.5 通用 Mac 注意事项

## 7. 结论：实际该用什么，以及为什么

### 7.1 按零件类型分流

| 你要做的事 | 2026-11 的现实答案 | 为什么 |
|---|---|---|
| **有尺寸要求的机械件**（支架、法兰、关节） | **LLM 写 build123d/CadQuery Python → STEP，配"测量-再断言"契约。** 本机已有 `earthtojake/text-to-cad` 全套技能（27,173★, MIT） | 唯一能同时给你 B-rep、命名参数、可改尺寸、可用 DFM/出图/切片的路径。基准上限 61%，但 30% 零分来自"没测量就宣称完成"——加上测量回路可把静默失败从 14.1% 压到 3.2% |
| **需要参考造型 / 概念可视化 / 游戏资产 / 渲染** | **Meshy 7.1 / Tripo H3.1 / fal.ai 上的 trellis-2** | 人类偏好上它们领先（benchmark.ai：Hi3D v3.0 > Meshy 7.1 > Tripo H3.1 > Hunyuan3D 3.1 > TRELLIS.2）。**但绝不要当零件来源** |
| **要"看起来像"某个实物的快速复刻** | Tripo H3.1（$0.20–0.50/次，含 PBR、multiview、可选 smart low-poly）或 Meshy | 但记住 Meshy 没有 STEP、Tripo 的 `auto_size` 默认关 |
| **要扫描件/照片 → 参数化模型** | **mesh2cad**（本地、确定性、MIT，6/6 真实零件 → 精确 STEP）或 **Backflip AI**（$10/件、1–5 分钟、声称全特征树 + STEP，但**无论文、无 repo、无权重、无第三方评估**） | 确定性路径在真实机械件上远可靠于学习型路径 |
| **要现成 CAD 内核 + AI** | **Zoo (KCL)**（唯一"模型即源码"的商用参数化栈，$0.0083/s）或 **SolidCraft**（17,788★，Apache-2.0，但自认"AI agents & MCP 2/8 done"） | KCL 是源码即模型；SolidCraft 是唯一成熟的开源参数化 CAD 应用 |
| **要嵌在 agent 里（无头）** | **build123d-mcp**（27工具，纯 Python）或 **mesh2cad** MCP | 唯一两个完全无头、许可证干净的 |
| **要云端生成** | fal.ai 或 Replicate（按次/按秒），或直接用 Meshy/Tripo 的 REST | 没有 OpenAI 兼容端点，需要自己写轮询 |

### 7.2 三条硬规则（如果只记三句）

1. **凡是"看起来对但说不清尺寸"的东西，一律不能进装配。** 独立证据链：TRELLIS.2 体积误差 317.9%（OmniMech）→ 95 百分位二面角 73.11°（Procedura）→ 切片成功率 17%（Hi3D）→ 六个模型**没有一个**输出 STEP/B-rep/公差。
2. **text-to-mesh 唯一可靠的用法是当"草图/参考图"，让 CAD 那边重新建。** 网格→参数化有两条路：确定性的 mesh2cad（真机械件上最靠谱）和学习型的 CADENA/CADFather/CADMAGEDDON（更强但仍"恢复不了设计意图"）。
3. **别让模型自己宣布完成。** 2026 年最被低估的工程结论：**失败率下降来自契约（measure-then-claim），不来自更大的模型**。每个 CAD agent 都应该先渲染、先测量、先校验，再声明 done。

### 7.3 你这台机器（18GB M3 Pro）的具体起点

1. **立刻可用、零风险**：SF3D（官方 MPS/CPU）+ `earthtojake/text-to-cad`（已装）。机械件走后者。
2. **要 PBR 纹理**：装 `dgrauet/Hunyuan3D-2.1-mlx`，用 INT8（约 6GB 峰值），18GB 内存跑512 分辨率约 9 分钟。
3. **要 TRELLIS.2 质量**：`pwilkin/trellis.cpp`（需自己编译，无 macOS 预编译二进制）。
4. **要更好的人类偏好**：直接打 API（Tripo H3.1 $0.20 起 / Meshy 7.1 Pro $20 起 / fal.ai trellis-2 $0.25 起）——你的 18GB 跑不出 Meshy 7.1 的质量。

## 8. 明确未能证实的（请勿当事实引用）

1. TRELLIS.2 是否为 "CVPR 2026 最佳学生论文" —— arXiv 无注释，官方奖项页 404，**仅第三方聚合站声称**。

4. **不存在**专门测"文生 3D 网格尺寸精度"的基准（OmniMech 最接近，但其网格基线用的是工程图输入，比产品照片更难）。
5. Hi3D 3.0 / Twinkle3D（arXiv 2610.11685）的**代码与权重** —— GitHub 404，HF `hi3d-official` 组织里只有 v1.0；v1.0 报告明确拒绝与3.0 对比。它是**唯一明确宣称"2048³ 水密三角网格"**的工作，但不开源。
6. FILIGREE3D（arXiv 2609.34900）的代码 —— 未找到 repo，arXiv 无 comment 字段。
7. **CADAgent 作为 arXiv 论文不存在**；**"Zoo Kernels" 不存在**；**"Keras" CAD 语言不存在**；**cadquery.ai 不存在**（域名不通 + Wayback 零存档）。
8. Backflip AI：无论文、无 repo、无权重、无第三方评估、"部署在某大型汽车厂"的说法无出处；SOC 2 尚在补 Type II。
9. Adam（adam.new）：**没有任何精度数字**；其开源产品 CADAM（5,455★, GPL-3.0）是 OpenSCAD/STL/DXF 网格路线，付费产品才是 B-rep 路线。
10. Topoheal 普查的**旧版每生成器缺陷率已被作者撤回**；我引用的是 2026-08-17 重跑后的 v1.0 表。同时它自述 *"The corpus is a snapshot... a row here describes the model version captured at collection time, not the vendor's current output."*
11. Rodin/Hyper3D 与 Stability 的确切关系 —— **未找到任何剥离公告**，只有 "© 2026 Deemos Corporation" 页脚和失效的 `rodin.stability.ai`。
